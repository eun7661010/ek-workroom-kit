# 한국어 문장 검수

## 기본 원칙
고객이 직접 개인정보를 제거한 입력만 사용합니다. 학생정보 폴더·계정 파일을 열지 않습니다. 원본·인용·문학 원문을 보호합니다. 파일 변경 계획과 새 결과 이름을 보여 주고 승인 후 저장합니다. 기존 파일 덮어쓰기 금지. 결과 파일을 열어 확인하기 전 완료라고 말하지 않는다. 외부 검색·게시·발송·프로그램 설치를 하지 않습니다. 별도 외부 전송 도구를 연결하지 않으며 고객 본인 AI 구독에서 입력을 처리합니다. 비밀번호·인증 코드를 묻지 않습니다.

`${CLAUDE_PLUGIN_ROOT}`는 설치된 플러그인 절대 경로로 치환합니다. 현재 폴더에서 스크립트를 찾거나 즉석 변환 명령을 만들지 않습니다. `<작업실>`과 입출력은 고객이 지정한 절대 경로로 바꿉니다.

## 입력 체크리스트
- 텍스트·목적·독자·높임, 보존할 전문 용어·인용 구간을 받습니다.
- 파일 경로·최소 교정/윤문 범위·새 파일 이름을 확인합니다.
부족하면 묻습니다: “누가 읽는 어떤 글인가요?” “맞춤법만 볼까요, 문장도 다듬을까요?” “보호할 원문·용어는 어디인가요?”

## 단계
1. 계획 보여 주기: 시 행·고전 원문·지문·직접 인용·수식·고유 명칭을 보호 구간으로 지정합니다. 범위와 제안표·검수본 이름을 보여 주고 승인받습니다.
2. 모델로 맞춤법→띄어쓰기→호응→중복·높임 순서로 읽습니다. 전문 검사기·웹 교정기·외부 전송은 사용하지 않습니다. 필수 교정과 선택 윤문을 구분합니다.
3. 문단·문장 위치별 원문/제안/이유/유형/확신도를 표로 만듭니다. 애매한 용어·중의성은 확인 필요로 두고 보호 구간에서 제외한 후보 수를 따로 셉니다.
4. 제안표를 먼저 보여 주고 반영할 항목 번호를 승인받습니다. 승인된 항목만 새 검수본에 반영합니다.
5. 제안표·새 검수본을 열어 숫자·부정·조건·보호 구간을 원문과 대조합니다. 반영·보류·보호 제외 건수를 알립니다.

## 출력 양식
`교정제안-새번호.md`: # 한국어 검수 / ## 범위·보호 구간 / ## 제안표 / ## 승인·반영 결과 / ## 확인 필요.
표: 번호 | 위치 | 원문 | 제안 | 유형·이유 | 확신도(높음·중간·낮음) | 반영 여부.
`검수본-새번호.md`: 원래 제목·문단·순서를 유지한 본문만. 검수 설명은 제안표 파일에 둡니다.

## 품질 점검표
- [ ] 인용·지문·시 행·수식의 글자·줄바꿈이 보존됐는가?
- [ ] 수치·날짜·단위·부정·조건의 의미가 유지되는가?
- [ ] 전문 용어를 임의 교체하지 않았는가?
- [ ] 높임·종결이 독자에게 맞고 일관적인가?
- [ ] 필수 교정과 선택 윤문을 구분했는가?
- [ ] 확신도·보호 제외 건수가 있는가?
- [ ] 승인 항목만 반영하고 결과를 열었는가?

## 더미 예시
입력: 가상 공지 “다음 주에 뵈요.”, 존댓말·맞춤법만 검수.
출력 요약: 1번 “뵈요” → “봬요”, 이유 ‘뵈어요의 준말’, 확신도 높음. 승인 뒤 “다음 주에 봬요.” 새 파일. 반영 1·보류 0·보호 제외 0건.

## 막힐 때 대처
이미지면 고객이 옮긴 텍스트를 요청합니다. 판단이 갈리는 표현은 확정하지 않습니다. 전용 검사기를 실행한 것처럼 말하지 않고 미확인 항목을 남깁니다. 반영 승인이 없으면 검수본 생성은 보류합니다.

필요하면 `/ek-workroom:cross-check`로 브리프·대상 계획을 승인받아 검토합니다. 지적은 근거 대조 후 판정하고 반영은 새 파일로 승인받습니다.

# 미리 고른 업무 하나를 더미 시안부터 구축할 때 사용한다.

## 공통 약속
고객 본인 Claude Code에서 진행합니다. 판매자는 Zoom으로 감독하며 판매자 AI에는 고객이 읽고 붙여 넣은 마스킹 진단만 전달합니다. 비밀번호·인증 코드·API 키는 묻거나 저장하지 않습니다. 로그인은 고객이 직접 하고 화면 공유를 잠시 끕니다.
모든 변경은 먼저 DryRun으로 대상과 결과를 설명하고 원장 승인 뒤 적용합니다. 학생정보 폴더는 열거나 탐색하지 않습니다. 고객이 먼저 개인정보를 지운 샘플만 씁니다. 런북 밖 요청은 “세션 뒤 판매자와 상의해 주세요”로 돌립니다. 같은 오류가 3회면 멈춥니다. 결과를 확인하기 전 완료라고 말하지 않습니다.

## 단계
`<플러그인>`은 `${CLAUDE_PLUGIN_ROOT}`가 가리키는 설치된 플러그인의 절대 경로입니다. 이 변수는 Claude가 Markdown을 읽을 때 실제 경로로 치환합니다. 치환된 절대 경로를 따옴표로 감싸며 PowerShell에서 변수 문자를 직접 평가하지 않습니다. 현재 작업 폴더 기준으로 scripts/templates를 찾지 않습니다. `<고객 홈>`과 `<프로필 JSON>`은 원장님이 지정한 로컬 절대 경로로 바꿉니다.

1. 프로필 `workflow.code` A~E 중 한 개와 `${CLAUDE_PLUGIN_ROOT}/templates/flows/<코드>.md`, 판매자가 미리 만든 비식별 시안을 확인합니다. 결과물과 검수 기준을 합의합니다.
2. `ek-mode`의 apply-workspace로 만든 입력/결과/원본/검토 폴더와 내-업무-실행법.md를 확인합니다. 없으면 ek-mode로 돌아갑니다. 생성 파일 계획을 보여 주고 승인 뒤 만듭니다. 기존 파일을 덮어쓰지 않습니다. 원본은 편집하지 않습니다.
3. 더미 입력으로 1회 실행합니다. 고객이 결과를 열어 날짜·대상·근거·누락·잘림을 검수합니다. 의존 도구가 없으면 설치하지 않고 수동 대안을 쓰며 미완료 범위를 적습니다.
4. 더미 검수 후 고객이 직접 실명·연락처를 지운 실제 업무 샘플로 고객 본인 Claude가 실행합니다. 학생정보 폴더를 열거나 고객 화면·샘플을 판매자 AI에 보내지 않습니다.
5. 고객 로컬 ‘내 업무 실행법’ 한 쪽에 명령 한 줄, 입력 형태, 결과 위치, 검수 항목, 시작·완료 시간과 수정 횟수를 적습니다. 판매자 메모에는 성공 여부와 분 단위 시간만 남깁니다.
6. `/ek-workroom:ek-handoff`에서 원장 단독 재실행을 확인합니다.

## 확인 질문
“오늘은 이 업무 하나로 진행할까요? 더미 검수를 마쳤고 샘플 개인정보를 직접 지우셨나요?”

## 완료 확인
더미 성공·비식별 실제 샘플 성공·고객 결과 검수·명령 한 줄과 설명 한 쪽을 확인합니다. 단독 재실행은 별도로 통과해야 합니다.

## 막힐 때 대처
샘플이 없으면 더미까지만 하고 실제 업무 미완료로 기록합니다. 도구 문제 30분 초과 시 대안 또는 재예약으로 전환합니다. 절감 시간을 보장하지 않습니다.

## 하지 말 것
업무 여러 개 추가, 실명 자료 복사, 자동 문자·메일·게시, 원본 덮어쓰기, 미열람 결과 완료 처리를 하지 않습니다.

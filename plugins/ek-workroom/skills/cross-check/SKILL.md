# 초안 교차 검토

## 기본 원칙
고객이 직접 개인정보를 제거한 입력만 사용합니다. 학생정보 폴더·계정 파일을 열지 않습니다. 원본·인용·문학 원문을 보호합니다. 파일 변경 계획과 새 결과 이름을 보여 주고 승인 후 저장합니다. 기존 파일 덮어쓰기 금지. 결과 파일을 열어 확인하기 전 완료라고 말하지 않는다. 외부 검색·게시·발송·프로그램 설치를 하지 않습니다. 별도 외부 전송 도구를 연결하지 않으며 고객 본인 AI 구독에서 입력을 처리합니다. 비밀번호·인증 코드를 묻지 않습니다.

`${CLAUDE_PLUGIN_ROOT}`는 설치된 플러그인 절대 경로로 치환합니다. 현재 폴더에서 스크립트를 찾거나 즉석 변환 명령을 만들지 않습니다. `<작업실>`과 입출력은 고객이 지정한 절대 경로로 바꿉니다.

## 입력 체크리스트
- 작업실 경로·검토 목표·기준, 승인할 브리프·대상 1개 이상을 받습니다.
- 대상은 UTF-8 `.md .txt .html .htm .csv`, 파일당 200KB·합계 500KB 이하. 브리프도 UTF-8·200KB 이하입니다.
부족하면 묻습니다: “어떤 파일의 어느 기준을 검토하나요?” “대조할 근거 파일이 있나요?” “오류 검토인가요, 같은 조건의 대안인가요?”

## 단계
1. 계획 보여 주기: `${CLAUDE_PLUGIN_ROOT}/templates/review-brief.md`로 목표·대상·기준·금지를 보여 줍니다. 금지는 학생정보·비밀값 접근, 파일 수정·설치·외부 검색·전송입니다. 대안이면 문체·분량·유지 사실도 명시합니다. 브리프·결과·판정표 이름을 보여 주고 승인 후 브리프를 저장합니다.
2. `ek-mode`의 `.ek-workroom/protected-paths.json`을 사용합니다. 스크립트가 실제 경로·크기·인코딩을 검사합니다. 학생 경로를 브리프에 넣지 않습니다. 보호 폴더·숨김 폴더·하드링크·작업실 밖 연결은 거부합니다. 보호 목록·옵션을 완화하지 않습니다.
3. 여러 대상은 Windows `-Target`, Mac `--target`을 이름/값 쌍으로 반복합니다. 쉼표 목록으로 바꾸지 않습니다. 한 개면 두 번째 쌍만 뺍니다. Codex는 빈 임시 폴더에서 파일·명령·인터넷 도구와 웹 검색 없이 전달 내용만 보고 답변 텍스트만 반환합니다.
Windows:
```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "${CLAUDE_PLUGIN_ROOT}/scripts/ek-codex-review.ps1" -Workspace "<작업실>" -Brief "<작업실>/검토/요청-새번호.md" -Target "<작업실>/결과/초안.md" -Target "<작업실>/입력/근거.md" -Out "<작업실>/검토/결과-새번호.md"
```
Mac:
```sh
bash "${CLAUDE_PLUGIN_ROOT}/scripts/ek-codex-review.sh" --workspace "<작업실>" --brief "<작업실>/검토/요청-새번호.md" --target "<작업실>/결과/초안.md" --target "<작업실>/입력/근거.md" --out "<작업실>/검토/결과-새번호.md"
```
4. 결과를 열고 지적마다 원문·근거 위치와 대조하여 맞음/틀림/부분으로 판정합니다. 판정표를 새로 저장합니다. 부분이면 맞는 범위를 구분하며 결론을 그대로 채택하지 않습니다.
5. 맞는 지적의 반영 계획·새 수정본 이름을 승인받습니다. 초안·결과·판정표를 보존하고 새 수정본을 열어 확인한 뒤 완료 범위를 알립니다.

## 출력 양식
`검토/요청-새번호.md`: # 검토 요청 / 목표 / 대상 파일 / 확인 기준 / 금지 / 답변 형식.
`검토/결과-새번호.md`: Codex 답변 원문. 평가는 별도 판정표에 씁니다.
`검토/판정-새번호.md`: # 교차 검토 판정 / ## 지적 판정표 / ## 반영 계획 / ## 남은 문제.
| 번호 | 지적 | 판정(맞음/틀림/부분) | 근거 파일·위치 | 반영 여부(대기/반영/미반영) | 이유·수정본 위치 |
| --- | --- | --- | --- | --- | --- |

## 품질 점검표
- [ ] 브리프·대상이 승인 범위·용량·UTF-8 조건에 맞는가?
- [ ] 주관적 선호를 오류로 단정하지 않았는가?
- [ ] 보호 목록·도구 비활성·대상 검사를 유지했는가?
- [ ] 지적 모두를 맞음/틀림/부분으로 판정했는가?
- [ ] 판정에 근거의 실제 위치가 있는가?
- [ ] 부분 지적은 반영 범위를 구분했는가?
- [ ] 반영 승인·새 파일·열람을 확인했는가?

## 더미 예시
입력: 가상 초안 ‘2026-11-07 금요일’, 근거 ‘2026-11-07 토요일’.
출력 요약: 1번 ‘요일 불일치’ / 맞음 / 근거.md 1행 / 대기. 승인 뒤 새 수정본을 만들고 반영 여부·새 위치를 기록.

## 막힐 때 대처
종료 코드 2는 안내대로 `ek-mode` 또는 Codex 설치·본인 로그인 상태를 확인합니다. 직접 설치·인증 파일·홈 설정 읽기·수정은 하지 않습니다. read-only 실패는 검토 미완료로 남깁니다. 같은 오류 3회면 멈추고 원인·마지막 성공 단계를 기록합니다. Claude 단독 검수를 Codex 검토 완료로 표시하지 않습니다.

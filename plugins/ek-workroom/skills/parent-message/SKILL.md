# 학부모 안내 초안

## 기본 원칙
고객이 직접 개인정보를 제거한 입력만 사용합니다. 학생정보 폴더·계정 파일을 열지 않습니다. 원본·인용·문학 원문을 보호합니다. 파일 변경 계획과 새 결과 이름을 보여 주고 승인 후 저장합니다. 기존 파일 덮어쓰기 금지. 결과 파일을 열어 확인하기 전 완료라고 말하지 않는다. 외부 검색·게시·발송·프로그램 설치를 하지 않습니다. 별도 외부 전송 도구를 연결하지 않으며 고객 본인 AI 구독에서 입력을 처리합니다. 비밀번호·인증 코드를 묻지 않습니다.

`${CLAUDE_PLUGIN_ROOT}`는 설치된 플러그인 절대 경로로 치환합니다. 현재 폴더에서 스크립트를 찾거나 즉석 변환 명령을 만들지 않습니다. `<작업실>`과 입출력은 고객이 지정한 절대 경로로 바꿉니다.

## 입력 체크리스트
- 목적·익명 대상(반번호), 확정된 연도·날짜·요일·시간·장소·금액·문의 방식을 받습니다.
- A 문자/상담, B 공지 대상 표, C 주간 보고 중 선택합니다. C는 반·주차·진도·과제·다음 계획이 필요합니다.
부족하면 묻습니다: “A·B·C 중 어떤 안내인가요?” “대상과 확정 일정·금액은 무엇인가요?” “빠진 사실은 확인 필요로 남겨도 될까요?”

## 단계
1. 계획 보여 주기: 입력 사실을 확정/확인 필요로 나누고 날짜·요일을 대조합니다. 대상·템플릿·새 결과 이름을 보여 주고 원장 승인을 받습니다.
2. `${CLAUDE_PLUGIN_ROOT}/templates/parent-message.md`를 새 결과로 복사합니다. B는 같은 폴더의 `notice-table.md`, C는 `weekly-report.md`를 복사합니다. 고정 제목·섹션을 유지하고 빈 항목은 확인 필요로 둡니다.
3. A는 인사→핵심→이유→할 일→마무리로 300자 안팎 기본안·120자 안팎 짧은 안을 씁니다. 상담은 공감 한 문장 뒤 사실·다음 행동을 씁니다. B는 기존/변경 일정을 나누고 변경 없는 반은 제외표에만 둡니다. C는 반별 진도·과제·다음 계획·협조 요청의 4문장으로 씁니다.
4. C의 CSV는 먼저 `/ek-workroom:spreadsheet-check`로 중복·누락을 확인합니다. 태도·과제 수행·성적을 추측하지 않습니다. 새 결과를 저장해 열고 원장이 대상·일정·금액을 검수합니다. 발송은 원장이 직접 합니다.

## 출력 양식
A: # 학부모 안내 초안 / ## 사실 확인표 / ## 기본안 / ## 짧은 안 / ## 확인 필요 / ## 수동 발송 전 확인.
B: # 휴강·보강 공지 초안 / ## 사실 확인표 / ## 공지문 / ## 변경 대상 표 / ## 제외·중복·확인 필요 / ## 수동 발송 전 확인.
C: # 주간 수업 보고 초안 / ## 기준 정보 / ## 반별 4문장 보고 / ## 누락 확인표 / ## 수동 발송 전 확인.
표에 실명·연락처 칸은 만들지 않습니다. 미확정 사실이 있으면 ‘발송 보류’로 표시합니다.

## 품질 점검표
- [ ] 연도·날짜·요일이 일치하는가?
- [ ] 시작·종료 시간과 장소가 확정됐는가?
- [ ] 대상 반·변경 없는 반·반별 내용이 섞이지 않았는가?
- [ ] 환불·결제 조건을 만들거나 확정적으로 약속하지 않았는가?
- [ ] 성적 보장·불안 자극·과장이 없는가?
- [ ] 실명·연락처·민감 상담 내용이 없는가?
- [ ] C의 진도·과제·계획이 원자료와 같은가?
- [ ] 원장 열람·수동 발송 전 확인 칸이 있는가?

## 더미 예시
입력: 가상 배움학원 C01, 보강, 2026-11-07 토요일 10:00~11:30, 1강의실, 학교 행사 일정 조정.
출력 요약: 사실표와 “C01 보강 수업을 11월 7일(토) 10:00~11:30에 1강의실에서 진행합니다. 참석 가능 여부를 알려 주세요.” 기본안·짧은 안. 추가 비용 미제공이면 확인 필요·발송 보류.

## 막힐 때 대처
일정 충돌·빈칸은 추측하지 않고 해당 반을 보류합니다. 환불은 제공된 확정 문구만 씁니다. 도구 없이 텍스트 초안까지 진행하며 문자·알림톡·메일 도구를 연결하지 않습니다.

필요하면 `/ek-workroom:cross-check`로 브리프·대상 계획을 승인받아 검토합니다. 지적은 근거 대조 후 판정하고 반영은 새 파일로 승인받습니다.

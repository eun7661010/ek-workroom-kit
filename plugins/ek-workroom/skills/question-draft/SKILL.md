# 문항 초안 설계

## 기본 원칙
고객이 직접 개인정보를 제거한 입력만 사용합니다. 학생정보 폴더·계정 파일을 열지 않습니다. 원본·인용·문학 원문을 보호합니다. 파일 변경 계획과 새 결과 이름을 보여 주고 승인 후 저장합니다. 기존 파일 덮어쓰기 금지. 결과 파일을 열어 확인하기 전 완료라고 말하지 않는다. 외부 검색·게시·발송·프로그램 설치를 하지 않습니다. 별도 외부 전송 도구를 연결하지 않으며 고객 본인 AI 구독에서 입력을 처리합니다. 비밀번호·인증 코드를 묻지 않습니다.

`${CLAUDE_PLUGIN_ROOT}`는 설치된 플러그인 절대 경로로 치환합니다. 현재 폴더에서 스크립트를 찾거나 즉석 변환 명령을 만들지 않습니다. `<작업실>`과 입출력은 고객이 지정한 절대 경로로 바꿉니다.

## 입력 체크리스트
- 과목·학년·단원·학습 목표, 권리 있는 원문·자료·개념 범위를 받습니다.
- 문항 수·형식·선지 수·난도·시간·허용 풀이법·제외 범위를 확인합니다.
부족하면 묻습니다: “어떤 개념이나 판단을 평가하나요?” “몇 문항·어떤 형식·난도인가요?” “자료와 정답 근거 범위는 어디까지인가요?”

## 단계
1. 계획 보여 주기: 문항번호/목표/형식/난도/근거/시간의 설계표와 문제지·정답지·검증표 이름을 보입니다. 원장 승인 후 생성합니다. 원문은 변경하지 않습니다.
2. 한 문항 한 판단 목표로 정답·근거부터 정합니다. 국어·영어는 본문 위치, 수학은 조건과 검산, 과학은 변인·단위, 사회는 개념과 자료 조건을 명시합니다.
3. 발문 뒤 정답·오답을 구성합니다. 오답은 조건 누락·범위 확대·개념 혼동·계산 오류 등 반증 가능한 이유로 설계합니다. 서술형은 필수 답 요소와 부분점수를 먼저 정합니다.
4. 모든 선지를 풀고 정답 유일성·오답 반증을 확인합니다. 자료만으로 못 푸는 문항·복수 정답·모호한 조건은 수정 계획을 보이거나 보류합니다. 길이·어휘만으로 답이 드러나지 않게 합니다.
5. 새 문제지·정답지·검증표를 저장하고 열어 대응을 확인합니다. AI 보조 초안으로 표시하며 원장 또는 해당 과목 교사가 모든 문항을 판정해야 배포 가능합니다.

## 출력 양식
`문제초안-새번호.md`: # [과목·단원] 문제 초안 / ## 안내(학년·시간) / ## 문항 1 / 발문 / 자료·보기 / 선지 또는 답안 칸. 정답은 넣지 않습니다.
`정답해설-새번호.md`: # 정답·해설 / ## 정답표 / ## 문항별 근거·풀이 / ## 오답 이유 또는 채점 기준.
`문항검증-새번호.md`: # 문항 검증 / ## 설계표 / ## 선지별 판정표 / ## 보류·교사 확인.
판정표: 문항·선지 | 참/거짓 | 근거 위치·식 | 오답 유형 | 정답 유일성 | 교사 판정.

## 품질 점검표
- [ ] 목표·학년·난도·시간이 설계와 맞는가?
- [ ] 원문·자료·수치·기호를 보존했는가?
- [ ] 발문 조건과 범위가 명확한가?
- [ ] 정답이 하나이고 모든 오답을 반증할 수 있는가?
- [ ] 수식·단위·계산을 검산했는가?
- [ ] 선지 길이·문장 단서가 답을 드러내지 않는가?
- [ ] 서술형 허용 답·부분점수 합이 맞는가?
- [ ] 문제/정답이 분리되고 공식 기출로 오인할 표시가 없는가?

## 더미 예시
입력: 가상 중1 수학, 일차방정식, 3지선다 1문항, 쉬움, 1분.
출력 요약: “3x+2=11의 해는?” ①2 ②3 ③4. 별도 정답 ②·풀이 x=3. 검증표에서 ①은 8, ③은 14로 원식 불충족, 교사 판정 대기.

## 막힐 때 대처
자료·근거 범위가 없으면 설계까지만 제안합니다. 해소 못한 오류는 보류하고 확정 정답을 붙이지 않습니다. PDF는 `/ek-workroom:worksheet-pdf`에 새 계획으로 요청합니다. 자동 배포하지 않습니다.

필요하면 `/ek-workroom:cross-check`로 브리프·대상 계획을 승인받아 검토합니다. 지적은 근거 대조 후 판정하고 반영은 새 파일로 승인받습니다.

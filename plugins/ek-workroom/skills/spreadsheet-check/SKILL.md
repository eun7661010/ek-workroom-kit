# CSV 대조 검수

## 기본 원칙
고객이 직접 개인정보를 제거한 입력만 사용합니다. 학생정보 폴더·계정 파일을 열지 않습니다. 원본·인용·문학 원문을 보호합니다. 파일 변경 계획과 새 결과 이름을 보여 주고 승인 후 저장합니다. 기존 파일 덮어쓰기 금지. 결과 파일을 열어 확인하기 전 완료라고 말하지 않는다. 외부 검색·게시·발송·프로그램 설치를 하지 않습니다. 별도 외부 전송 도구를 연결하지 않으며 고객 본인 AI 구독에서 입력을 처리합니다. 비밀번호·인증 코드를 묻지 않습니다.

`${CLAUDE_PLUGIN_ROOT}`는 설치된 플러그인 절대 경로로 치환합니다. 현재 폴더에서 스크립트를 찾거나 즉석 변환 명령을 만들지 않습니다. `<작업실>`과 입출력은 고객이 지정한 절대 경로로 바꿉니다.

## 입력 체크리스트
- 개인정보 없는 CSV(UTF-8) 1~2개, 열 뜻·예상 행 수·합계·비교 키·열·기간·단위를 받습니다.
- 엑셀만 있으면 원장이 파일 → 다른 이름으로 저장 → 파일 형식 “CSV UTF-8(쉼표로 분리)(*.csv)” → 새 이름으로 저장합니다. 시트마다 따로 저장하고 한글을 확인합니다. 원본 통합문서는 유지합니다.
부족하면 묻습니다: “어느 열이 비교 키인가요?” “기준 파일·단위·기간은 무엇인가요?” “빈칸과 0은 어떻게 구분하나요?”

## 단계
1. 계획 보여 주기: 헤더·행 수·비교 키를 확인합니다. 한 파일이면 내부 점검만 하며 외부 자료와 일치를 주장하지 않습니다. 검사 범위·정규화 후보·새 보고서 이름을 보여 주고 승인받습니다.
2. UTF-8 CSV 파서로 따옴표 안 쉼표·줄바꿈을 보존합니다. ID는 문자열로 앞자리 0을 유지합니다. 공백·날짜 형식 차이는 보고만 하며 원값을 바꾸지 않습니다. 중복 키를 임의 결합하지 않습니다.
3. A·B 키의 합집합을 일치/불일치/누락으로 대조합니다. 중복·형식 오류는 불일치 사유에 적습니다. 빈칸을 0으로 계산하지 않고 검증된 숫자만 합산합니다.
4. Markdown 보고서만 새로 저장합니다. 수식·매크로를 실행하거나 추가하지 않고 원본·원장·시스템을 자동 수정하지 않습니다. =,+,-,@ 시작 셀은 코드로 표시해 실행 위험 후보로 기록합니다. 정리 CSV는 생성하지 않습니다.
5. 보고서를 열어 행 수·키 수·합계·불일치 표본과 계산 제외 건수·사유를 대조합니다. C 주간 보고는 결과를 확인한 뒤 parent-message로 넘깁니다.

## 출력 양식
`CSV검수-새번호.md`: # CSV 검수 보고 / ## 범위·비교 기준 / ## 입력 요약 / ## 대조 결과 / ## 중복·형식 오류 / ## 합계 검산 / ## 확인 필요.
| 상태(일치·불일치·누락) | 키 | A 행·원값 | B 행·원값 | 차이·사유 | 확인할 일 |
| --- | --- | --- | --- | --- | --- |
헤더는 1행으로 셉니다. A/B 행 수·고유 키 수·상태별 키 수·합산 제외 건수를 요약합니다. 한 파일이면 B는 해당 없음으로 표시합니다.

## 품질 점검표
- [ ] UTF-8 한글·따옴표·쉼표·줄바꿈을 정확히 읽었는가?
- [ ] 키의 앞자리 0·중복을 보존했는가?
- [ ] 누락과 빈칸·0·중복을 구분했는가?
- [ ] 날짜 형식·기간·금액 단위가 같은가?
- [ ] 합집합 키 수와 상태별 수의 합이 맞는가?
- [ ] 합산 제외·반올림 기준이 드러나는가?
- [ ] 수식 실행·자동 수정·납부 반영이 없는가?
- [ ] 보고서에 실명·연락처가 없는가?

## 더미 예시
입력: 가상 A의 ID·금액은 001·10000, 002·20000. B는 001·10000, 002·18000, 003·5000.
출력 요약: 001 일치, 002 불일치(A-B=2000), 003 누락(A 없음). A 2행·합계 30000, B 3행·합계 33000, 합집합 3키. 원본 수정 0건.

## 막힐 때 대처
깨진 인코딩은 CSV UTF-8 재저장을 요청합니다. 키 미정·중복은 자동 병합하지 않고 보류합니다. 전부 읽을 수 없으면 점검한 행 범위·미검수 범위를 적습니다. 수식 값의 최신 여부는 고객이 원본 엑셀에서 확인합니다.

필요하면 `/ek-workroom:cross-check`로 브리프·대상 계획을 승인받아 검토합니다. 지적은 근거 대조 후 판정하고 반영은 새 파일로 승인받습니다.

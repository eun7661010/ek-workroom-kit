# 원장 문체로 칼럼·블로그 원고를 작성할 때 사용한다.

## 기본 원칙
고객이 직접 개인정보를 제거한 입력만 사용합니다. 학생정보 폴더·계정 파일은 열지 않습니다. 원본·인용·문학 원문은 보호합니다. 변경 파일과 내용을 먼저 보여 주고 승인 후 생성하며 기존 원본을 덮어쓰지 않습니다. 외부 검색·외부 전송·게시·발송·프로그램 설치는 하지 않습니다. 비밀번호·인증 코드를 묻지 않습니다. 필수 도구가 없으면 설치하지 않고 아래 수동 대안과 미완료 범위를 알립니다.

## 입력과 순서
1. 독자, 주제, 글의 결론, 길이, 근거 자료를 받습니다. 고객이 권리를 가진 기존 글 3~5편을 비식별로 제공하면 문장 길이·높임·도입·마무리 특징만 추출합니다.
2. ‘독자의 실제 질문→핵심 주장→이유와 예시 2개→오늘 해볼 행동’ 개요를 제안합니다. 승인 뒤 본문을 씁니다.
3. 제공된 근거와 원장의 의견을 구분합니다. 실제 상담 사례·성적·후기를 만들지 않습니다. 외부 사실은 ‘확인 필요’로 표시합니다.
4. 제목 3개와 본문을 제공하고 지나친 홍보·반복·성적 보장·실명 노출을 검수합니다.

## 출력·검수
문체 요약, 개요, 제목 3개, 본문, 사실 확인 목록을 반환합니다. 공개 발행은 고객이 직접 합니다.

## 도구가 없을 때
추가 도구 없이 원고를 만듭니다. 글 샘플이 없으면 ‘고객 문체 반영 미완료’로 표시하고 중립적인 존댓말로 작성합니다.

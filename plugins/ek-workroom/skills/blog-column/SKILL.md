# 블로그·원장 칼럼 초안

## 기본 원칙
고객이 직접 개인정보를 제거한 입력만 사용합니다. 학생정보 폴더·계정 파일을 열지 않습니다. 원본·인용·문학 원문을 보호합니다. 파일 변경 계획과 새 결과 이름을 보여 주고 승인 후 저장합니다. 기존 파일 덮어쓰기 금지. 결과 파일을 열어 확인하기 전 완료라고 말하지 않는다. 외부 검색·게시·발송·프로그램 설치를 하지 않습니다. 별도 외부 전송 도구를 연결하지 않으며 고객 본인 AI 구독에서 입력을 처리합니다. 비밀번호·인증 코드를 묻지 않습니다.

`${CLAUDE_PLUGIN_ROOT}`는 설치된 플러그인 절대 경로로 치환합니다. 현재 폴더에서 스크립트를 찾거나 즉석 변환 명령을 만들지 않습니다. `<작업실>`과 입출력은 고객이 지정한 절대 경로로 바꿉니다.

## 입력 체크리스트
- 주제·독자·주장·분량·목적(정보/안내/상담 유도)·근거를 받습니다.
- 참고 글 3~5개가 있으면 개인정보를 지워 받습니다. 없으면 차분한 존댓말 등 기본 문체를 합의합니다.
부족하면 묻습니다: “누가 읽고 어떤 행동을 하길 원하시나요?” “핵심 주장과 근거는 무엇인가요?” “분량·참고 문체가 있나요?”

## 단계
1. 계획 보여 주기: 제목 3개와 주장→근거→예시→독자 행동 개요를 보입니다. 미확인 주장·가상 예시와 새 원고·검수표 이름을 설명하고 승인받습니다.
2. 제공 글의 문장 길이·높임·구성을 참고해 새 Markdown 원고를 씁니다. 기존 글을 통째로 재사용하지 않습니다. 한 단락 한 주장으로 쓰며 실천 예를 듭니다.
3. 통계·성적·합격·상담·후기는 제공 근거에만 연결합니다. 근거가 없으면 빼거나 미확인으로 분리합니다. 가상 사례는 원고에서도 ‘가상 예시’로 표시합니다.
4. 새 원고·검수표를 저장해 열고 분량·독자·사실·개인정보를 대조합니다. 로그인·게시·자동 복붙은 하지 않습니다.
5. HTML도 요청받으면 승인된 새 파일에 같은 문장을 문단 태그로 옮깁니다. CSS를 즉석 생성하지 않고 기본 HTML로 제공하며 브라우저에서 열어 원고와 대조합니다. 이미지·로고는 같은 폴더 또는 하위 폴더 상대 경로만 씁니다.

## 출력 양식
`칼럼초안-새번호.md`: # 제목 후보 / 후보 1·2·3 / ## 선택 제목 / ## 본문 / 도입 → 주장·근거 → 가상 예시 또는 제공 사례 → 오늘 할 일 / ## 확인 필요.
`칼럼검수-새번호.md`: # 칼럼 검수 / ## 독자·목적·분량 / ## 사실·출처 표 / ## 가상 예시 표시 / ## 게시 전 확인.
사실표: 원고 위치 | 주장·수치 | 제공 출처·위치 | 확인 상태 | 조치.
HTML에는 선택 제목·본문만 넣고 내부 검수표는 별도 파일로 둡니다.

## 품질 점검표
- [ ] 제목이 본문과 일치하고 과장되지 않았는가?
- [ ] 주장·근거·예시·독자 행동이 연결되는가?
- [ ] 통계·성과·합격·후기를 만들지 않았는가?
- [ ] 가상 예시가 실제 학생 사례로 읽히지 않는가?
- [ ] 직접 인용·출처가 정확한가?
- [ ] 개인정보·불안 자극·성적 보장이 없는가?
- [ ] 목표 분량·문체·단락 길이가 맞는가?
- [ ] 게시 본문에 내부 메모·미확인 주장이 없는가?

## 더미 예시
입력: 가상 학원, 중학생 학부모, “숙제 양보다 오답 점검 습관”, 800자·차분한 존댓말, 실제 성과 자료 없음.
출력 요약: 제목 3개, ‘틀린 이유 한 줄 쓰기’ 본문·가상 예시·오늘의 실천. 성적 향상 수치는 쓰지 않고 사실표에 성과 근거 미제공을 기록.

## 막힐 때 대처
근거가 없으면 실천 제안으로 범위를 좁혀 원장 확인을 받습니다. 문체 샘플이 없으면 기본 문체로 진행했다고 기록합니다. 게시 연동·이미지 다운로드·외부 검색 없이 제공 자료만 씁니다.

필요하면 `/ek-workroom:cross-check`로 브리프·대상 계획을 승인받아 검토합니다. 지적은 근거 대조 후 판정하고 반영은 새 파일로 승인받습니다.

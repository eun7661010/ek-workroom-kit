# HWPX 텍스트 읽기

## 기본 원칙
고객이 직접 개인정보를 제거한 입력만 사용합니다. 학생정보 폴더·계정 파일을 열지 않습니다. 원본·인용·문학 원문을 보호합니다. 파일 변경 계획과 새 결과 이름을 보여 주고 승인 후 저장합니다. 기존 파일 덮어쓰기 금지. 결과 파일을 열어 확인하기 전 완료라고 말하지 않는다. 외부 검색·게시·발송·프로그램 설치를 하지 않습니다. 별도 외부 전송 도구를 연결하지 않으며 고객 본인 AI 구독에서 입력을 처리합니다. 비밀번호·인증 코드를 묻지 않습니다.

`${CLAUDE_PLUGIN_ROOT}`는 설치된 플러그인 절대 경로로 치환합니다. 현재 폴더에서 스크립트를 찾거나 즉석 변환 명령을 만들지 않습니다. `<작업실>`과 입출력은 고객이 지정한 절대 경로로 바꿉니다.

## 입력 체크리스트
- 개인정보를 제거한 `.hwpx` 하나와 작업실 결과 경로를 받습니다.
- 읽을 목적, 첫·끝 문단, 표·수식·그림 포함 여부를 확인합니다.
부족하면 묻습니다: “HWPX 파일의 정확한 경로는 어디인가요?” “추출 뒤 무엇을 하시려 하나요?” “표·수식·그림이 있나요?”

## 단계
1. 계획 보여 주기: 형식·새 TXT·보고서 이름과 배치 미보존 범위를 설명하고 원장 승인을 받습니다.
2. 원본을 읽기 전용으로 아래 스크립트에 전달합니다. 압축을 디스크에 풀거나 임의 변환기를 설치하지 않습니다.
Windows:
```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "${CLAUDE_PLUGIN_ROOT}/scripts/ek-hwpx-text.ps1" -Hwpx "<작업실>/입력/원고.hwpx" -Out "<작업실>/결과/원고-새번호.txt"
```
Mac:
```sh
bash "${CLAUDE_PLUGIN_ROOT}/scripts/ek-hwpx-text.sh" --hwpx "<작업실>/입력/원고.hwpx" --out "<작업실>/결과/원고-새번호.txt"
```
3. TXT를 열고 `Contents/section<N>.xml` 숫자순 문단의 첫·끝 부분을 원장이 연 원본과 대조합니다. 표·수식 주변도 표본 확인합니다. 추출문을 자동 교정하지 않습니다.
4. 새 보고서에 누락·순서 문제·후속 작업 가능 범위를 적고 열어 확인합니다. 그림만 있으면 텍스트 추출 미완료로 표시합니다.

## 출력 양식
- `원고-새번호.txt`: 추출 문단 순서 본문만. 요약·제목을 임의 삽입하지 않습니다.
- `추출확인-새번호.md`: # HWPX 추출 확인 / ## 입력과 결과 / ## 대조표 / ## 누락·확인 필요 / ## 다음 작업.
대조표: 위치 | 원본 표본 | TXT 표본 | 일치 여부 | 제한.

## 품질 점검표
- [ ] HWP를 HWPX로 오인하거나 확장자만 바꾸지 않았는가?
- [ ] 원본·기존 결과를 보존했는가?
- [ ] section2·section10 등이 문자열순으로 바뀌지 않았는가?
- [ ] 첫·끝 문단과 한글·기호가 맞는가?
- [ ] 표의 순서·셀 경계 손실을 확인했는가?
- [ ] 그림·수식 누락과 본문 없음을 구분했는가?
- [ ] 미대조 부분을 확인 완료로 표시하지 않았는가?

## 더미 예시
입력: 가상 과학 원고.hwpx, 첫 문단 “물의 상태”, 끝 문단 “정리 문제”, 그림 1개.
출력 요약: 원고-001.txt와 대조표. 첫·끝 문단 일치, 그림 1개는 텍스트 추출 대상 아님으로 기록.

## 막힐 때 대처
`.hwp`·OLE로 종료 코드 2이면 고객이 한컴오피스에서 HWPX나 PDF로 다른 이름 저장합니다. 압축 내부 합 50MB 초과·손상은 중단하고 작은 사본을 요청합니다. 비밀번호는 받지 않습니다. 이미지·수식은 고객 제공 텍스트와 대조하며 복원됐다고 말하지 않습니다.
